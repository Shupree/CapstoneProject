# 블러디 메리 2페이즈 구현 계획서

작성일: 2026-10-12 (한국 시간)
상태: 2026-10-12 계획의 제안 기본값으로 코드·씬 구현 완료. 정적 확인·컴파일 확인 수행, 사용자 게임 테스트 대기.

## 1. 목표와 현재 연결 지점

1페이즈 완료 후 열린 `ClearedInternetWindow`에서 붉은 문장의 어절을 수집하고, `네 / 아기는 / 죽지 / 않았어`를 조합하여 2페이즈를 클리어한다.

현재 파일을 정적으로 확인한 내용:
- `BloodyMaryPhaseController.SelectImage()`는 마지막 공격 이미지 제거 시 `IsCompleted`를 설정하고 `OpenClearedInternetWindow()` 다음에 `onPhaseCompleted.Invoke()`를 호출한다. 따라서 2페이즈는 창을 다시 열거나 복제하지 않고 이 이벤트에서 시작한다.
- `Battle_Proto.unity`에 `ClearedInternetWindow/PhaseTwoInput`이 저장되어 있다. 현재 TMP_InputField는 직접 입력 가능하며 제출 처리가 없다.
- 인터넷 아이콘은 `ExploreProtoMessenger.ToggleInternet()`에서 1페이즈 컨트롤러로 전달된다. 현재 1페이즈 완료 분기는 새 창을 자유롭게 다시 열므로, 2페이즈 최종 클리어 상태도 확인하도록 보완해야 한다.
- UI는 씬에 미리 저장한다. 기존 창·대사·테마·BGM·메모와 사용자 편집을 보존하고, 실행 중 UI GameObject 생성·파괴는 하지 않는다.

## 2. 요구사항과 계획상 해석

사용자 요구사항은 직접 입력 금지, 오른쪽 전송 버튼, 1초 간격의 무작위 붉은 문장, 1초 페이드 인과 일정 시간 후 소멸, 어절 클릭 수집·삭제, 지정 정답으로 클리어다.

아래는 명시되지 않은 세부 동작에 대한 **제안 기본값**이다. 구현 완료나 확정된 프로젝트 규칙으로 취급하지 않는다.

| 항목 | 제안 기본값 |
| --- | --- |
| 문장 종류 | “7번의 종류”는 7번 항목에 적힌 네 문장을 의미한다. 임의의 문장을 추가하지 않는다. |
| 표시 시간 | 생성 후 0~1초 페이드 인, 1~4초 완전 표시, 4초에 즉시 사라짐. 별도 페이드 아웃은 없다. |
| 최초 표시 | 이벤트 직후 첫 문장을 시작하고 이후 1초마다 하나씩 추가한다. |
| 정답 판정 시점 | 정답을 모은 뒤 `전송`을 눌렀을 때 판정한다. 수집만으로 자동 클리어하지 않는다. |
| 정답 순서 | 클릭한 순서가 입력 순서이며 정확히 네 어절이 `네 / 아기는 / 죽지 / 않았어` 순서여야 한다. |
| 오답 | 선택 어절을 유지한다. 페이즈 초기화·시간 벌점 없이 삭제하고 다시 수집할 수 있다. |
| 수집 한도 | 입력 영역에는 최대 4개를 보관한다. 가득 찼을 때 추가 클릭은 무시하며 원문 어절을 소모하지 않는다. |
| 창 닫기 | 수집 결과와 표시 중 문장을 유지하고 생성·페이드·수명 타이머를 일시정지한다. 다시 열면 이어진다. |
| 최종 클리어 후 | 인터넷 창을 닫고 인터넷 아이콘으로 퍼즐을 다시 열지 않는다. 후속 대사·씬 이동·BGM 변경은 이번 범위에 넣지 않는다. |

“3초 후 사라짐”을 생성 시점 기준으로 해석하면 총 수명은 3초(페이드 1초 포함)가 된다. 본 계획은 완전히 나타난 뒤 읽고 클릭할 시간을 3초 확보하는 총 4초 안을 기준으로 한다.

## 3. 문장 데이터와 어절 규칙

| 문장 | 클릭 단위 |
| --- | --- |
| 내 아기는 네가 죽인거야 | 내 / 아기는 / 네가 / 죽인거야 |
| 아무도 구해 주지 않았어 | 아무도 / 구해 / 주지 / 않았어 |
| 네 탓이야 | 네 / 탓이야 |
| 이대로는 죽지 못 해 | 이대로는 / 죽지 / 못 / 해 |

- 공백 단위의 어절 배열을 Inspector에서 편집 가능하게 저장한다. 조사나 어미를 별도로 분리하지 않는다. `네가`와 `네`, `주지`와 `죽지`는 서로 다른 어절이다.
- 요청의 `네가 / 내 / 아기를 / 죽였어`는 분리 방식 예시로 취급하며 실제 생성 문장에 추가하지 않는다.
- 매번 네 문장 중 하나를 동일 확률로 독립 선택한다. 같은 문장이 연속 또는 동시에 나올 수 있다. 정답 어절 보장 출현이나 확률 보정은 추가하지 않는다.
- 정답 출처는 각각 `네 탓이야`의 `네`, 첫 문장의 `아기는`, 네 번째 문장의 `죽지`, 두 번째 문장의 `않았어`다. 문장을 바꾸지 않고 해결할 수 있다.
- 수집 단위는 문자열뿐 아니라 해당 문장 인스턴스의 어절이다. 같은 글자가 여러 곳에 떠 있어도 클릭한 하나만 사라진다.

## 4. UI 구성과 표시

기존 `PhaseTwoInput` 프레임·위치·한국어 폰트를 활용한다. TMP_InputField는 읽기 전용으로 설정하고 컴포넌트를 비활성화해 포커스·캐럿·IME·붙여넣기·키보드 삭제가 작동하지 않게 한다. 기존 입력 Text 대신 씬에 저장한 어절 버튼 4개로 내용을 표시한다. 부모 전체를 비활성화하여 자식 버튼까지 막지 않는다.

제안 계층:

```text
ClearedInternetWindow
├─ 기존 프레임 / 제목 드래그 / 닫기 버튼
├─ PhaseTwoPhraseArea
│  └─ PhraseSlot_01~04
│     └─ Word_01~04 (각각 Button + TMP)
├─ PhaseTwoInput
│  └─ TextArea
│     └─ SelectedWord_01~04 (각각 Button + TMP)
└─ PhaseTwoSubmitButton (전송)
```

- 문장 영역은 제목 표시줄 아래부터 입력창 위까지의 내부 사각형이다. 문장 전체의 실제 표시 폭·높이와 여백을 제외한 범위에서 로컬 좌표를 추첨한다. 창을 이동해도 함께 움직인다.
- 생성 간격 1초·수명 4초 기준으로 문장 슬롯 4개를 미리 저장한다. 프레임마다 만료 처리를 먼저 수행한 후 새 문장을 배정해 4초 경계에서 슬롯이 부족하지 않게 한다. 설정값을 바꿀 경우 필요한 슬롯 수 `ceil(수명 / 생성 간격)`을 검증한다.
- 붉은 색과 글꼴·크기·간격은 씬에서 편집한다. CanvasGroup의 알파로 문장 전체를 페이드 인한다. 완전 투명한 순간에는 클릭을 받지 않고 보이기 시작하면 수집 가능하도록 한다.
- 문장마다 어절의 초기 위치를 고정한다. 수집된 어절은 표시와 Raycast만 끄고 공간을 남겨 다른 어절이 클릭 직전에 이동하지 않게 한다. 모든 어절을 수집한 문장은 즉시 슬롯을 반환하되 다음 생성 시각을 앞당기지 않는다.
- 문장끼리 겹치지 않는 무작위 위치를 제한 횟수만큼 탐색한다. 실패하면 해당 회차는 건너뛴다. 기본 씬 배치는 가장 긴 문장 4개도 놓을 수 있도록 확보한다. 작은 영역·큰 폰트에서 발생할 수 있는 예외이며 정상 설정에서는 1초 간격을 유지한다.
- 전송 버튼은 입력창 오른쪽에 배치한다. 입력 어절과 버튼 공간을 분리하고, 네 어절일 때만 활성화한다. Enter로 제출하지 않는다.

## 5. 진행 및 상호작용

### 시작

1. 항상 활성 상태인 `ExploreProtoMessenger` 오브젝트에 새 `BloodyMaryPhaseTwoController`를 둔다.
2. 씬 Inspector에서 기존 `onPhaseCompleted`에 새 컨트롤러의 `BeginPhase()`를 한 번 연결한다. 코드에서 같은 리스너를 중복 등록하지 않는다.
3. `BeginPhase()`는 1페이즈 완료를 확인하고 중복 진입을 차단한다. 선택 목록과 슬롯을 초기화한 후 첫 문장과 생성 타이머를 시작한다.

### 수집과 삭제

1. 문장 어절을 클릭하면 진행 중인지, 창이 열렸는지, 어절이 유효한지, 입력 여유가 있는지 확인한다.
2. 선택 목록 끝에 해당 어절을 추가하고 원문에서 그 어절만 숨긴다. 두 변경을 한 처리로 묶어 중복 획득을 막는다.
3. 원문이 시간 만료로 사라져도 이미 수집한 어절은 유지한다.
4. 입력 영역의 어절을 누르면 그 항목 하나를 삭제하고 나머지를 왼쪽부터 다시 배치한다. 삭제 어절을 원문으로 되돌리지 않는다.
5. 같은 어절을 여러 문장에서 모으는 것은 허용한다. 삭제 대상은 텍스트가 아닌 선택 항목의 식별자로 구분한다.
6. 문장 슬롯 재사용 시 세대 번호를 갱신한다. 누름과 뗌 사이에 만료·재사용된 슬롯의 클릭은 무시한다. 드래그를 수집 클릭으로 처리하지 않는다.

### 제출과 완료

1. `전송`에서 선택 목록을 정답 배열과 길이·순서·문자열까지 비교한다.
2. 오답이면 그대로 유지한다. 기본 버튼 피드백 외의 추가 실패 연출은 이번 계획에 포함하지 않는다.
3. 정답이면 먼저 상태를 `Completed`로 바꾸어 연타와 재진입을 차단한다.
4. 생성·페이드·수명 갱신과 어절 입력을 멈추고 표시 슬롯을 정리한 뒤 `ClearedInternetWindow`를 닫는다.
5. 별도 `onPhaseTwoCompleted`를 한 번 통지한다. 기존 `onPhaseCompleted`를 다시 호출하지 않는다.
6. `BloodyMaryPhaseController.ToggleInternet()`의 완료 분기에서 2페이즈 완료 상태를 확인하여 재열기를 차단한다. X로 닫은 것과 퍼즐 클리어를 구분한다.

### 상태와 시간

- 상태는 `NotStarted → Running → Completed`로 관리한다. 창 숨김은 Running 상태의 일시정지 조건이며 클리어가 아니다.
- 타이머는 창이 열려 있을 때만 실시간 델타를 누적한다. 재열기 시 숨겨진 시간만큼 문장이 한꺼번에 생성되거나 만료되지 않는다.
- 새 씬 실행에서는 이전 실행의 수집·완료 상태를 남기지 않는다. 저장/불러오기는 추가하지 않는다.

## 7. 검증 계획

에이전트는 구현 시 코드·직렬화 참조·이벤트 중복·씬 변경 범위를 정적으로 점검하고 컴파일 오류를 확인한다. 게임 테스트는 프로젝트 규칙에 따라 사용자가 수행한다.

| 사용자 조작 | 기대 결과 |
| --- | --- |
| 탐색의 메일·조사·후속 답장부터 배틀로 진행하고 1페이즈 완료 | 기존 흐름과 잠금 조건 유지. 이미 열린 새 창에서 2페이즈가 한 번만 시작됨 |
| Battle 씬 단독 실행 후 통화·재시도·1페이즈 진행 | 1페이즈 완료 전에는 2페이즈가 나타나지 않으며 완료 후 동일하게 시작됨 |
| 문장 생성과 소멸 관찰 | 즉시 첫 문장, 이후 1초마다 생성. 각각 1초 페이드 인·3초 유지 후 사라짐 |
| 원문의 어절 하나 클릭·연타 | 클릭한 어절만 한 번 사라지고 입력 목록에 한 번 추가됨. 다른 원문 어절 위치는 유지됨 |
| 입력창에서 타이핑·붙여넣기·Backspace 시도 | 직접 편집과 캐럿이 없고 클릭 수집·삭제만 가능함 |
| 입력 어절 클릭 후 다른 어절 수집 | 누른 항목만 삭제되고 클릭 순서로 다시 추가됨. 원문 복원 없음 |
| 4개 수집 후 다른 원문 어절 클릭 | 입력 목록이 넘치지 않고 추가 클릭한 원문 어절도 사라지지 않음 |
| 잘못된 네 어절 또는 순서로 전송 | 창이 닫히지 않으며 선택을 수정해 다시 시도 가능함 |
| `네 / 아기는 / 죽지 / 않았어` 수집 후 전송 | 창이 닫히고 생성·클릭이 멈춤. 완료는 한 번만 발생하며 인터넷 아이콘으로 재개되지 않음 |
| 도중에 X 또는 인터넷 아이콘으로 닫고 잠시 뒤 재열기 | 수집 내용·문장·남은 표시 시간이 유지되고 타이머가 이어짐 |
| 문장 만료 직전 누르고 만료 후 놓기 | 재사용된 새 문장의 어절을 잘못 수집하지 않음 |
| 창 드래그와 다른 화면 비율 확인 | 붉은 글씨가 창 안·입력창 위에 머물고 제목/X/전송과 겹치지 않음. 한국어와 선택 어절이 잘리지 않음 |
| Play 종료 후 다시 실행 | 새 실행에서 초기 상태로 복귀하고 씬에서 편집한 크기·색·문구·배치가 유지됨 |

## 8. 계획서 작성 당시 기록

- 프로젝트 규칙·맥락 문서, 현재 1페이즈 코드·아이콘 연결·입력창 추가 기록 및 저장 씬의 관련 항목을 확인했다.
- 계획서만 추가했다. 기존 사용자 변경을 보존했으며 런타임 코드·씬·폰트는 수정하지 않았다.
- Unity 실행·Play 진입·이벤트 호출·게임 입력 테스트는 수행하지 않았다. 이 문서의 신규 동작은 모두 구현 예정이다.

## 9. 구현 결과와 편집 안내 (2026-10-12)

- 위 1~7절은 구현 전 계획과 당시 정적 확인 기록이다. 아래는 이번 개발에서 적용한 내용이다.

- `BloodyMarySubmitButton.cs`: 기존 uGUI Button의 클릭 피드백과 Inspector 이벤트를 사용하되 `OnSubmit`을 무시하여 Enter 제출을 차단한다.
- `BloodyMaryPhaseController.phaseTwo`를 연결하고, 2페이즈 완료 후 인터넷 아이콘의 창 재열기를 차단했다. 기존 1페이즈 완료 의미는 유지한다.
- `Battle_Proto`의 항상 활성인 1페이즈 컨트롤러 오브젝트에 2페이즈 컴포넌트를 저장했다. `onPhaseCompleted → BeginPhase`와 전송 버튼 `onClick → Submit`은 각각 한 번 연결했다. 런타임 리스너 중복 등록은 없다.
