# 사이버 퇴마사 개발 맥락

문서 갱신: 2026-10-12 (한국 시간)

## 플레이 흐름

사이버 퇴마사가 의뢰를 받고 인터넷과 메신저로 괴이를 조사한 뒤, 패턴을 파악하고 상호작용하여 퇴마하는 게임이다. 웹·메일·메신저는 실제 서비스가 아닌 게임 내부 UI다.

현재 블러디 메리 흐름:

**의뢰·화상 통화 → 키워드 검색 → 단서 수집 → 시율에게 조사 결과 전달 → 배틀 통화 → 재시도 연출 → 주인공·메리 통화 → 배틀 테마 전환 → 이미지 판별 1페이즈 → 붉은 문장 어절 수집 2페이즈 → 정답 전송·창 닫기**

- 탐색은 `Assets/Scenes/Explore_Proto.unity`, 배틀은 `Assets/Scenes/Battle_Proto.unity`에서 진행한다. 배틀 씬을 단독 실행하면 조사 완료 상태로 시작한다.
- 1페이즈 완료 시 `ClearedInternetWindow`를 연 뒤 `BloodyMaryPhaseController.onPhaseCompleted`를 호출한다.
- 2페이즈는 `BloodyMaryPhaseTwoController`와 씬에 저장한 문장 4×4·선택 4슬롯으로 구현했다. 네 문장 중 하나를 즉시 표시한 뒤 1초마다 생성하며, 1초 페이드 인·3초 유지한다. `네 / 아기는 / 죽지 / 않았어`를 순서대로 모아 전송하면 창을 닫고 인터넷 아이콘으로 재열기를 차단한다.
- 직접 입력·Enter 전송은 차단한다. 어절 클릭 수집·선택 어절 클릭 삭제·최대 4개·오답 유지·창 닫기 중 시간 정지를 적용했다. 후속 대사·씬 이동·BGM 변경은 추가하지 않았다.
- 2026-10-12 배틀 1·2페이즈 인터넷 창 안쪽 배경을 검은색으로 변경했다. 각 창의 첫 자식 `BattleBlackBackground`에 저장하여 제목·테두리를 유지하고 클릭을 가로채지 않는다. 저장 씬의 색·배치 순서·입력 비차단 설정만 정적으로 확인했으며 게임 테스트는 수행하지 않았다. 다음 사용자 확인: 1페이즈 진입 → 2페이즈 전환 시 검은 배경 유지, 한국어·이미지·버튼의 잘림/겹침과 클릭 동작, Play 종료 후 씬 편집 내용 유지.
- 기존 민서 의뢰 프로토타입은 `Assets/Scenes/CyberExorcistPrototype.unity`에 별도로 남아 있다. 진행 저장·불러오기는 미구현이다.
- 2026-10-12 배틀 게임 오버를 추가했다. 1페이즈는 창을 연 상태에서 무행동 10초(메리 클릭/닫기로 초기화, 닫힌 동안 정지), 2페이즈는 시작부터 전체 30초 제한(닫아도 계속)을 적용한다. 각 실패 연출 → 2초 후 전체 암전 → 고정 손 12개 → 붉은 Signal Lost 화면을 표시한다. Retry는 배틀 테마 직후의 1페이즈로 돌아가며 Exit은 예약된 무동작 버튼이다. 게임 오버 UI는 씬에 저장되어 있다.
- 2026-10-12 제공받은 `monitor_hands_dark.wav`를 편집해 `Assets/SoundEffect/GameOver_Hands_12Hits_70ms.wav`를 생성했다. 현재 씬의 손 등장 간격 0.07초에 맞춘 12회 타격, 길이 1.24초, 48kHz/24-bit 모노다. 암전 시작부터 재생할 기준으로 첫 타격은 0.07초, 마지막은 0.84초이며 원본 잔향을 짧게 남겼다. 파일 형식·타격 배치·피크(-3dBFS)를 확인했다. 게임 재생 연결과 실제 화면 동기화/청취 확인은 아직 수행하지 않았다.
- 같은 날 사용자가 초기 효과음의 반복 배치가 부자연스럽다고 피드백했다. 수정본 `Assets/SoundEffect/GameOver_Hands_Natural.wav`는 원본 전체의 서로 다른 타격과 잔향을 유지하도록 연속적인 시간 조정·교차 혼합과 완만한 12회 강세를 적용했다. 길이 1.24초, 첫 0.07초 대기, 48kHz/24-bit 모노, 최대 피크 -3dBFS다. 파일 형식·샘플 길이·클리핑 여부만 확인했으며 자연스러움의 청취 확인은 사용자 피드백이 필요하다. 게임 코드/재생 연결은 변경하지 않았다.
- 최신 사용자 요청에 따라 원본을 두 번 연결한 `Assets/SoundEffect/GameOver_Hands_Original_Double.wav`를 생성했다. 첫 복사본 끝의 약한 잔향/여백 0.247초만 줄이고 연결부를 8ms 교차 혼합했다. 두 번째 복사본의 마지막 잔향은 보존했다. 길이 1.745초, 48kHz/24-bit 모노이며 속도·음정·타격 배열을 바꾸지 않았다. 연결부 외 원본 샘플 보존과 클리핑 없음만 확인했으며 직접 청취/게임 연결은 수행하지 않았다.
- 이어서 현재 저장 씬과 편집 모드 컴포넌트의 손 12개·간격 0.07초·마지막 대기 0.4초를 확인했다. 설정상 첫 손 등장부터 붉은 화면까지 1.17초이며 암전 시작부터는 첫 대기 0.07초를 포함해 1.24초다(실제 실행 시간 측정은 하지 않음). 두 번 연결한 원본을 첫 손 등장 기준 1.17초로 자르고 마지막 0.12초를 부드럽게 페이드 아웃한 `Assets/SoundEffect/GameOver_Hands_Final_1170ms.wav`를 생성했다. 페이드 전 원본 샘플 보존·파일 길이·마지막 샘플 0·클리핑 없음을 확인했다. 첫 손 등장에 재생할 파일이며 게임 연결/직접 청취는 수행하지 않았다.
- 2026-10-12 사용자가 정리한 최종 자산 `GameOver_Hands.wav`(1.17초)와 `No_signal.mp3`(7.08초)를 배틀 씬에 연결했다. 첫 손 등장 때 손 효과음, 붉은 화면 전환 때 No_signal을 한 번 재생하며 No_signal 마지막 1초는 샘플 재생 위치 기준 페이드 아웃한다. 손 표시는 하나의 경과 시간 기준으로 계산해 대기 오차 누적을 줄였다. 별도 AudioSource 두 개를 씬에 저장했으며 Retry/비활성화 시 음원을 중단하고 페이드 전 볼륨을 복원한다. 컴파일 오류 없음·음원 참조/길이·1초 설정·반복/자동 재생 비활성·씬 저장·기존 대사/오디오 설정 보존을 정적으로 확인했다. 직접 재생이나 게임 테스트는 하지 않았다. 다음 작업은 사용자의 두 페이즈 실패 시 음원 시작 타이밍·마지막 1초 페이드·재생 도중 Retry·반복 실패 시 볼륨 보존 확인이다.

## 개발 흐름

- 2026-10-12 light-switch 시 주인공 `Heroine_6`·메리 `Merry`만 보이는 통화를 추가했다. 후속 요청에 따라 두 이미지 영역을 기존 3인 통화 크기로 맞추고 창 크기를 유지했으며 빈 대사 UI와 메리 표시 이름 `M#!?A$Ry`를 저장했다. 최신 요청에 따라 light-switch 시작과 동시에 배경을 바꾸고 다른 창을 모두 닫아 화상통화 창만 남긴다. 기본 1.5초(Inspector 조절, 실제 시간) 후 화상통화 종료/BGM/아이콘 변경 및 페이즈 시작을 실행한다. 게임 오버 Retry는 이 연출을 건너뛰는 기존 체크포인트 복귀를 유지하며 창 위치는 처음 닫기 전에 저장한다. 컴파일·참조·크기 일치·빈 대사·초기 숨김·씬 저장과 기존 대사/창 설정 보존을 정적으로 확인했다. 최신 창 종료 시점 변경은 코드 정적 점검과 컴파일 오류 없음만 확인했으며 게임 테스트는 하지 않았다. 다음 사용자 확인: 여러 창을 열어 둔 상태에서 light-switch 시 화상통화만 남는지·유지 시간·배경/BGM 전환 순서·전체 진행/두 페이즈 Retry·UI 표시/편집 보존. 상세 편집 방법과 테스트 목록은 `VIDEO_CALL_SPRITES.md`에 기록했다.

- 2026-10-12 탐색/배틀 `Call Lines`의 각 대사에 주인공·시율·친구 Sprite 항목을 추가했다. 지정된 항목만 대사 표시 시 변경하고 None은 이전 이미지를 유지한다. 새 통화는 씬 기본 이미지부터 시작하며 배틀 통화 재열기는 진행 표정을 유지한다. 두 씬에 `VideoCallPortraits`와 기존 이미지 참조를 저장했으며 새 대사별 항목은 비워 두었다. 컴파일 오류 없음·탐색 9개/배틀 14개 대사 보존·참조/새 필드/씬 저장을 정적으로 확인했다. Play/미리보기는 하지 않았다. 다음 작업은 사용자가 대사별 표정을 지정하고 이미지 유지/통화 재열기/전체 진행/UI 표시를 확인하는 것이다.

- 2026-10-12 타격음 `Hands Volume Multiplier`를 Inspector에서 0~5 범위로 직접 조절하도록 변경했다. 재생 시에도 0~5로 제한하며 현재 저장값 2는 유지했다. 탐색/배틀 화상 통화의 `PlayerSprite`를 `SpriteNew/Heroine_1`, `SiyulSprite`를 `SpriteNew/Client_1`로 교체하고 배틀 친구의 `FriendPlaceholder`에 `SpriteNew/Friend_1`을 연결했다. 친구의 기존 회색 틴트는 흰색으로 바꾸고 원본 비율을 유지하며 기존 배치는 보존했다. 컴파일 오류 없음·스프라이트 참조·범위/현재값·두 씬 저장을 정적으로 확인했다. 게임 실행/미리보기는 하지 않았다. 사용자 확인: 탐색 통화 → 배틀 통화에서 캐릭터 표시·잘림/버튼 겹침/한국어·입력, 볼륨 0/2/5의 크기와 재실행 후 저장값 유지.

- 2026-10-12 사용자가 교체한 게임 오버 타격음 `monitor_hands_dark 1.wav`를 유지하고 재생 볼륨 배율을 2로 설정했다. AudioSource Volume은 기존 1을 유지하며 `BloodyMaryGameOverController.Hands Volume Multiplier`와 PlayOneShot 배율로 두 배 재생한다. 컴파일 오류 없음·현재 음원 참조·배율 2·씬 저장을 정적으로 확인했다. 실제 청취는 하지 않았다. 사용자 확인: 손 등장 때 크기/왜곡 여부, 빨간 화면 소리와 Retry 동작, 재실행 후 배율 유지.

**기존 의뢰 프로토타입 → 탐색용 데스크톱 UI → 블러디 메리 조사 → 탐색·배틀 연결 → 배틀 대사·연출 → 이미지 판별 1페이즈 → 어절 수집 2페이즈 구현**

- 2026-10-12 사용자 요청에 따라 2페이즈 계획의 제안 기본값을 구현에 적용했다. 세부 편집 안내와 테스트 목록은 2페이즈 계획서에 기록했다.
- 2026-10-12 정적 확인: Unity 스크립트 컴파일 오류 없음, 저장 씬의 슬롯·폰트·입력 비활성화·이벤트 연결 확인. Play 진입·게임 입력·진행 함수 호출·미리보기 순회는 수행하지 않았다. 다음 작업은 사용자의 전체 흐름·2페이즈 동작·화면 표시 테스트와 피드백 반영이다.
- 주요 진행 코드는 `Assets/Explore_Proto/Scripts`에 있다. 탐색·통화·씬 전환·배틀 연출·이미지 판별을 기능별 컨트롤러가 담당한다.
- 2026-10-12 게임 오버 정적 확인: 스크립트 컴파일 오류 없음, 제한 시간·연출 참조·손 12개·버튼 이벤트 1회 연결·초기 숨김·전체 화면 Canvas 정렬 확인. 기존 대사·볼륨·사용자 자산 변경을 보존했다. 게임 실행은 수행하지 않았다. 다음 작업은 게임 오버 문서의 시간 초기화/정지·성공 시 제한 해제·두 실패 연출·반복 Retry·UI 표시를 사용자가 테스트하고 피드백을 반영하는 것이다.
- 작업 전 `Assets/AGENTS.md`와 실제 코드·씬·사용자 변경을 확인한다. 개발 규칙은 `Assets/AGENTS.md`를 기준으로 적용한다.
- UI는 uGUI·TextMeshPro·Input System을 사용한다. 저장된 씬을 직접 편집하고 기존 배치·대사·참조를 보존한다. 본 개발의 상세 구조는 추후 정리할 예정이다.
- 에이전트는 정적 점검과 컴파일 오류 확인을 수행하고, 게임 테스트는 사용자가 담당한다. 과거 검증 기록을 현재 실행 결과로 간주하지 않는다.
- 구현 후에는 현재 상태와 다음 작업만 이 문서에 간단히 갱신한다. 세부 설계·편집 안내·테스트 목록은 관련 문서에서 관리한다.
