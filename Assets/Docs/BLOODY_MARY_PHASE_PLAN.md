# 블러디 메리 이미지 판별 페이즈 개발 계획서

작성일: 2026-10-12
상태: 계획만 작성. 코드·씬·리소스는 변경하지 않았으며 구현 및 게임 테스트는 수행하지 않음.

## 1. 목표와 요청 해석

배틀 테마 전환 이후 인터넷 창에서 공격 상태의 블러디 메리 이미지를 찾아 클릭하는 퇴마 페이즈를 진행한다. 일반 이미지를 누르면 첫 단계로 돌아가고, 세 단계를 연속으로 통과하면 페이즈를 종료한다.

요청 중 ‘18장 중 랜덤한 하나’는 앞뒤 수량과 충돌하므로, 최종 명시된 단계 표를 기준으로 계획한다. 즉 시작은 **12장 중 공격 이미지 1개**다.

| 단계 | 전체 이미지 | 시작 시 공격 이미지 | 해당 단계 완료 조건 |
| --- | ---: | ---: | --- |
| 1 | 12 | 1 | 공격 이미지 1개를 일반 이미지로 변경 |
| 2 | 18 | 2 | 공격 이미지 2개를 모두 일반 이미지로 변경 |
| 3 | 24 | 3 | 공격 이미지 3개를 모두 일반 이미지로 변경 |

## 2. 페이즈 진입과 아이콘 동작

현재 재시도 연출에서 노이즈가 끝나고 배경·아이콘 교체 및 창 닫기가 완료되는 시점에 퇴마 페이즈를 활성화한다. 재시도 버튼을 누른 순간에는 아직 진입하지 않는다.

| 요소 | 테마 전환 전 | 테마 전환 후 |
| --- | --- | --- |
| 메시지 아이콘 | 기존 메신저 기능 | 버튼 자체의 클릭 피드백은 표시하되 창·문구·알림·추가 효과음은 발생하지 않음 |
| 이모지 아이콘 | 기존 메모장 기능 | 메모장 열기·닫기 및 수집 정보 유지 |
| 인터넷 아이콘 | 기존 조사 검색 화면 | 블러디 메리 이미지 판별 창 열기 |
| 더보기 아이콘 | 기존 동작 | 추가 요구가 없으므로 기존 동작 유지 |

이미지 판별 창은 인터넷 아이콘을 눌렀을 때 열고, 테마 전환 직후 자동으로 띄우지 않는다. 기존 BGM과 배틀 테마는 유지한다.

메시지 버튼은 클릭 색상 변화·눌림 표시 등 기존 버튼 자체의 클릭 피드백을 유지한다. Button을 비활성화하거나 Interactable을 끄지 않고, 클릭 이후 메신저를 여는 기능만 실행하지 않는다. 반응이 없다는 안내 문구나 알림·추가 효과음은 발생시키지 않는다. 탐색 씬에는 이 제한을 적용하지 않는다.

## 3. 창과 이미지 배치

- 첨부 참고 이미지처럼 기존 인터넷 창의 프레임 안에 이미지 목록을 배치한다.
- **배치 제안:** 참고 이미지 기준으로 가로 3열, 아래 방향으로 행을 추가한다. 단계별로 4행·6행·8행이 된다.
- 각 이미지 크기는 단계가 바뀌어도 고정한다. 개수가 늘었다고 전체를 축소하거나 창에 맞춰 압축하지 않는다.
- 카드의 기준 크기는 기존 스프라이트와 씬의 Canvas/PPU 설정을 확인해 유지한다. 일반/공격 전환에서도 카드 RectTransform을 바꾸지 않는다. 두 이미지의 비율이 다르면 원본 비율을 보존하고 잘라내거나 늘여 그리지 않는다.
- 이미지 묶음은 창 내부 가로 중앙에 놓고, 위쪽 여백을 두어 참고 이미지의 구성을 반영한다. 창 높이를 넘는 부분은 아래로 이어진다.
- Viewport 밖 이미지는 마스크로 가리고 세로 스크롤로 접근한다. 화면 밖에도 공격 이미지가 선택될 수 있어야 한다.
- 휠과 드래그로 스크롤할 수 있게 하되, 스크롤 드래그를 이미지 클릭으로 판정하지 않는다.
- 창 닫기·다시 열기는 현재 단계와 남은 공격 이미지 및 스크롤 위치를 유지한다.

기존 ‘UI를 씬에 미리 배치한다’는 규칙에 따라 **24개 이미지 슬롯을 모두 Battle_Proto 씬에 저장**한다. 단계에 따라 앞의 12/18/24개만 활성화한다. ‘6개 추가’는 저장된 슬롯 6개를 더 표시하는 것으로 구현하며, 실행 중 UI를 생성하거나 재구성하지 않는다.

예상 계층(구현 시 기존 프레임 구조에 맞춰 조정):

```text
InternetWindow
└─ ExorcismContent
   └─ ImageScroll
      └─ Viewport
         └─ Content
            ├─ MaryImage_01
            ├─ …
            └─ MaryImage_24
```

조사용 검색·결과·상세 패널과 퇴마용 목록을 구분해, 테마 전환 후 두 화면이 겹치거나 기존 검색으로 돌아가지 않도록 한다.

## 4. 단계 진행 규칙

### 단계 시작

1. 단계에 맞는 수량만 활성화한다.
2. 모든 활성 슬롯을 일반 이미지로 초기화한다.
3. 활성 슬롯 전체에서 중복 없이 1/2/3개를 무작위 추출하여 공격 이미지로 바꾼다.
4. 단계 시작 및 실패 재시작 시 스크롤을 맨 위로 돌린다(계획상 기본 동작).

무작위 대상은 신규 6장에 한정하지 않는다. 직전 단계에서 공격 이미지였던 자리도 다음 추출에 다시 포함될 수 있다. 우연히 같은 위치가 다시 선택되는 것도 정상으로 처리한다.

### 공격 이미지 클릭

- 클릭한 슬롯의 공격 상태를 해제하고 일반 스프라이트로 바꾼다.
- 남은 공격 이미지가 있으면 같은 단계에서 계속한다.
- 모두 해제하면 1→2, 2→3단계로 즉시 진행한다. 이전 슬롯은 유지하고 아래에 6개를 더 표시한 뒤 전체 활성 슬롯에서 공격 대상을 새로 추출한다.
- 3단계의 공격 이미지 3개를 모두 해제하면 페이즈 완료로 전환한다.

### 일반 이미지 클릭

- 어떤 단계든 1단계로 되돌린다.
- 12개만 표시하고 모두 일반 이미지로 초기화한 뒤 공격 이미지 1개를 새로 추출한다.
- 되돌리는 범위는 이 이미지 판별 페이즈다. 통화·조사 기록·배틀 테마·BGM·메모는 되돌리지 않는다.
- 이미 공격 상태를 해제해 일반 이미지가 된 슬롯도 다시 누르면 실패 판정한다.
- 별도의 실패 문구·팝업·효과음은 요청되지 않았으므로 추가하지 않는다.

### 페이즈 종료

- 마지막 24개가 모두 일반 이미지인 상태를 남기고 추가 이미지 클릭 판정을 중지한다.
- 완료 알림을 내부적으로 한 번만 전달할 수 있도록 구성한다.
- 이후 대사·다음 페이즈·성공 화면·창 자동 닫기·BGM 변경은 이번 범위에 넣지 않는다. 후속 연출은 별도 기획 대상으로 남긴다.

## 5. 구현 구성안

| 대상 | 계획한 변경 |
| --- | --- |
| BattleProtoRetrySequence | 테마 교체와 창 닫기 완료 후 퇴마 페이즈 진입 통지 추가 |
| ExploreProtoMessenger | 배틀 퇴마 상태일 때 메시지 버튼의 클릭 피드백만 유지하고 메신저 열기는 차단. 인터넷은 퇴마 창으로 연결. 이모지 기능 유지 |
| 신규 페이즈 컨트롤러 | 단계, 활성 수량, 공격 슬롯 집합, 일반 클릭 초기화, 완료 여부 관리 |
| 이미지 슬롯 컴포넌트 | 클릭한 슬롯 번호 전달, 일반/공격 Sprite 표시, 드래그와 클릭 구분 |
| Battle_Proto 씬 | 스크롤 목록과 24개 슬롯, 컴포넌트 참조 저장 |

현재 코드의 HasStarted는 재시도 연출을 시작했다는 의미이므로, 퇴마 시작 판정에 그대로 사용하지 않는다. 테마 적용이 완료됐다는 별도 상태 또는 완료 이벤트를 사용한다.

Sprite 이름 비교 대신 슬롯별 공격 상태를 데이터로 관리한다. 초기화·단계 이동·완료 처리 중에는 클릭을 받지 않고, 한 번의 입력으로 여러 슬롯이나 여러 단계가 처리되지 않도록 한다. 버튼 연결은 중복 등록하지 않는다.

사용자가 Inspector에서 수정할 수 있도록 일반/공격 Sprite, 단계별 전체·공격 수량, 슬롯 목록, 스크롤 참조를 노출한다. 창 크기·이미지 크기·간격·여백은 저장된 씬에서 편집한다.

확인된 사용 에셋:

- 일반: `Assets/Sprite/ProtoType/bloody_mary.png`
- 공격: `Assets/Sprite/ProtoType/bloody_mary_attack.png`

## 6. 개발 순서

1. 기존 배틀 씬, 인터넷 프레임, Sprite 크기·비율·Import 설정을 확인한다.
2. 기존 UI를 보존하며 스크롤 영역과 24개 고정 크기 슬롯을 씬에 배치한다.
3. 단계 초기화·무작위 선정·클릭 판정·실패 초기화·완료 처리를 구현한다.
4. 테마 전환 완료 시점과 인터넷·메시지 아이콘 분기를 연결한다.
5. 저장된 참조·입력 설정·컴파일을 정적으로 점검하고 실제 구현 내용을 CONTEXT.md에 기록한다.
6. 아래 목록으로 사용자가 직접 게임 테스트를 진행하고 피드백을 반영한다.

## 7. 사용자 테스트 목록

| 조작 | 기대 결과 |
| --- | --- |
| 테마 전환 전에 메신저·인터넷 열기 | 기존 조사 동작 유지 |
| 테마 전환 후 메시지 아이콘 클릭 | 버튼의 클릭 색상·눌림 피드백은 표시되지만 창·알림·안내 메시지·추가 효과음은 발생하지 않음 |
| 이모지 아이콘 클릭 | 기존 메모장과 조사 기록 정상 표시 |
| 인터넷 아이콘 클릭 | 일반/공격 합계 12장, 공격 1개. 기존 검색 화면은 안 보임 |
| 아래로 스크롤 | 이미지 크기가 유지되며 모든 행에 접근 가능 |
| 이미지 위에서 스크롤 드래그 | 공격 해제나 실패 판정이 발생하지 않음 |
| 공격 1개 클릭 | 즉시 18장·공격 2개 단계로 이동 |
| 2단계 공격 중 하나만 클릭 | 18장 유지, 남은 공격은 1개 |
| 남은 공격 클릭 | 24장·공격 3개 단계로 이동 |
| 어느 단계에서든 일반 이미지 클릭 | 12장·공격 1개로 초기화, 스크롤 맨 위. 메모·테마·BGM 유지 |
| 여러 번 시작·초기화 | 공격 수량이 정확하고 중복 슬롯 없이 무작위 배치 |
| 창을 닫고 다시 열기 | 현재 단계·해제 상태·스크롤 유지, 공격 위치 재추첨 없음 |
| 3단계 공격 모두 클릭 | 24장이 일반 이미지가 되고 페이즈 완료, 이후 클릭으로 재시작되지 않음 |
| 새 Play 시작 | 완료 상태가 남지 않고 기존 배틀 준비 흐름에서 시작 |
| 다른 화면 비율에서 확인 | 이미지 크기·비율 유지, 창·버튼 겹침과 잘림 없이 스크롤 가능 |

에이전트는 Play 진입, 입력 시뮬레이션, 진행 함수 호출, 게임 검증 스크립트 실행을 하지 않는다. 정적 점검과 사용자 테스트 결과를 구분해 기록한다.
